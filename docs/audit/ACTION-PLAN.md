# Varniqa Skin Sciences — Prioritized Action Plan

## Phase 1: Critical fixes — Weeks 1–2

- Add verified medical registration, education and memberships.
- Add privacy, terms, medical disclaimer, editorial policy and WhatsApp safety microcopy.
- Make every service card actionable; add post-grid and sticky-mobile booking CTAs.
- Add visible, genuine GBP/review proof and synchronize schema.
- Replace categorical hair-transplant pain language with balanced clinician-reviewed copy.
- Validate deployed schema and confirm true 404 HTTP status.

## Phase 2: High-impact improvements — Weeks 3–6

- Build six core service hubs and first 5–8 high-intent condition pages.
- Add candidacy, diagnostic process, risks, alternatives, preparation, downtime, aftercare, FAQs and reviewer metadata to each.
- Reorganize services around patient intent and cross-link concerns to treatment modalities.
- Add “What to expect,” practical arrival guidance and consultation/response-time policies.
- Update sitemap, internal linking, canonical tags and service schema for every new page.

## Phase 3: Refinement — Month 2

- Reduce long-page density and group secondary FAQs in accessible disclosures.
- Strengthen the doctor module and replace generic differentiators with proof.
- Self-host/subset fonts, audit GTM and move CSS/JS to hashed immutable assets.
- Add verified professional/social profiles to visible links and `sameAs`.

## Phase 4: Monitoring — Ongoing

- Monitor GSC queries/pages, GBP actions, conversions and Core Web Vitals.
- Review clinical content and visible/schema freshness quarterly.
- Keep NAP, hours, review counts, profiles, sitemap and `llms.txt` synchronized.
- Build reputable medical/local citations and avoid thin suburb doorway pages.
